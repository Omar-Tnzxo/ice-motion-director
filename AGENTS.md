# Ice Motion Director: maintainer guide for agents

This file is for any agent or person who builds or edits this repository (Claude Code, Codex, Gemini, Cursor, humans). It records the project's goals and every decision the founder has made. Read it fully before changing anything. Users of the skill do not need it; the skill itself starts at the router skill.

Founder and owner: Omar-Tnzxo.

## What this repo is

One merged agent skill/plugin that turns a coding agent into a full motion studio: motion graphics and motion design from scratch, video editing (long-form, podcast, talking-head ads, shorts), remaking a film in the style of a reference, and pitching ideas. It merges the rules, workflows, references, templates and assets of 42 open-source video and motion sources (counted in `CREDITS.md` sections 1 to 4), plus the founder's own skills, into one deduplicated system.

## Non-negotiable product rules

1. **Same quality floor for every prompt: a full production company's output.** A one-line prompt such as "make an ad for <brand>" must still produce what a complete production house would deliver; the user never has to ask for that level. The agent fills the gaps from this repo's principles and workflow. Every request about a business (company, app, website, shop, product, service) starts with a researched business brief: what it is, who it serves, its product truth, market and competitors, brand identity and real material, current campaigns and tone. The business brief also covers the advertising rules of that industry and market and the ad policies of the target platforms. Then the full production pipeline runs by default, scaled to the film's size (micro, standard, long; see the production spine in `docs/maintainers/architecture.md`, which also sets the stage order per kind of film and keeps each workflow's own methods inside the stages): concept, script, storyboard, style frames, animatic, build, sound design and mix, independent reviews, and the delivery versions (languages, aspect ratios, cutdowns) the brief calls for. A detailed prompt or a design file (colors, direction, message, style) gives the same quality while obeying every stated spec. Prompt length changes who makes each decision, never the quality.
2. **No sameness across users.** Films must never converge on one look, palette, structure or workflow (the failure mode of generic AI websites). Required mechanisms:
   - Fresh research before decisions, dated with the runtime date, built from the user's brief (see rule 3).
   - Templates and demos are references, never defaults: a film must differ from its nearest template or demo on at least 4 of 6 axes (palette, type, layout, motion language, structure, sound).
   - A divergent pitch round: several directions, at least two of them unexpected, chosen by a critic after comparison.
   - A per-project fingerprint (palette, structure, motion language) stored locally; the next project may not repeat it.
   - A default-look gate: a film dominated by the stock AI palette (blue and purple) without a reason in the brief fails.
   - Every decision (color, type, rhythm, music, structure) is logged with its reason and source.
   - These mechanisms guard Ice's own choices, never the user's (founder decision, 2026-10-29). A look the user chose (a reference, a named style, the brand's own identity, a series look) is exempt from the template distance, the fingerprint (compared only between films without such a choice) and the unexpected directions of the pitch round, on the axes the choice fixes; research before decisions and the decision log stay. Canonical: `skills/ice-direction/references/anti-sameness.md` section 4a.
3. **Weak-agent-proof writing.** Assume a weak or hallucinating agent will follow every sentence literally on an unrelated request.
   - Never write a literal example search query or a single concrete example that could be copied out of context.
   - Research queries are assembled from brief slots: film type, industry or topic, audience, platform, language, runtime date. Every term in a query must trace to the user's prompt; a query with an untraceable term is not run.
   - Where an example helps, give slots, or several varied examples clearly marked as illustration only.
   - Before a file is done, ask: "If a weak agent applied this line literally to a different request, would it go wrong?" If yes, rewrite it.
4. **Ask before working: four choices for every open decision (founder decision, 2026-10-22).** At stage 01, after the quick research that makes the options real and before any concept or build work, the agent asks about every decision slot the user's words and supplied material leave open (canonical list: `skills/ice-direction/references/questions.md` section 1), even for a one-line prompt. Every question has exactly 4 options built from the brief and the research, the recommended one first with a one-line reason, plain words, and the user may always write their own answer; at most 4 questions per round, several rounds when more slots are open. Slots fixed by the user's words or supplied material are never asked (rule 9). Only the user's own words ("don't ask", "decide yourself") waive the questions; then every recommended option is taken and the first report lists each with its alternatives. A brief written by another agent, or a run condition, never waives, and silence is not a waiver: the run waits at 01. Free downloads (real media from public libraries and official sources) and free tool or model installs at pinned versions are never questions: Ice does them and records each one; a paid service, an account, a sign-in or spending still is (founder decision, 2026-10-29).
5. **Multi-agent decisions when details are missing.** Analysis, dated research, critique, consultation and a final approval for each major decision (for example color choices judged by their psychology for that audience and by current conventions for that film type). Builders never grade their own work; critics are separate and read-only. Depth over speed (founder decision, 2026-10-20): the per-stage approvers, the full crew and the decision log stay; do not trim them to make runs faster.
6. **Route by request type; conflicting rules are both right.** The router classifies the request (editing type, from-scratch film type, reference remake, ideation, industry, platform, language) and picks the workflow and engine. When two sources disagree (crossfades allowed or banned, slow camera push or stillness during holds), each rule is kept and scoped to the film types where it holds. Never pick one globally.
7. **One canonical rule per idea.** Duplicates across sources are merged into one rule so the agent is never given two versions of the same instruction.
8. **Real brands get their real material, never an invented look.** When the request names a real company, product or app, or asks for a film in a field where a reference brand helps, the agent researches it (dated today) and gathers its real material: site and app screens captured live, official press or brand kits, colors and fonts read from the brand's own site, official logos used untouched. UI mockups rebuild the real screens at 90 percent fidelity or better. A brand's look is never guessed; when material cannot be obtained, the agent says so and asks for it.
9. **Start where the user is.** A brief, idea, script, storyboard, design file, music, voiceover or footage that the user supplies is detected at intake, normalized into the canonical run file, marked user-supplied and locked, and only lightly validated (facts, timing fit, rights). Each supplied artifact is also checked for completeness against the fields its stage needs; when parts are missing, the agent tells the user once, in plain words, which parts are missing and offers two paths: attach them, or let the workflow research and fill them (asked as the `gaps` question of rule 4, research and fill recommended; taken without an answer only when the user waived the questions in their own words). Every filled gap is logged in `ice/DIRECTION.md` as a decision with its source, and the user's own parts stay untouched. The run starts at the first stage still missing, and stages whose inputs are ready run in parallel.
10. **Two audiences, both first class.**
   - **One prompt, for everyone, including non-technical users.** A capable agent runs the whole production spine in order from a plain prompt, short or very long; the user never needs to name a skill or type a command. Everything said to the user is plain language with no jargon; any missing tool is explained as one clear step for their operating system.
   - **Step by step, for people who want to steer.** Numbered stage commands, in the style of spec-kit, run one stage at a time. Each stage ends with a review card: what was made (with previews such as frames or contact sheets), the options that were considered and why this one won, the critic's notes, and the choices still open. The user can discuss, ask for alternatives or changes as many times as they like; the next stage starts only after they approve. The README documents both paths, the one-prompt path first.
11. **Arabic and RTL are first class.** Arabic typography, captions, bidi and motion rules apply whenever the language is Arabic or mixed.
12. **Run log (founder decision, 2026-10-21).** Every run logs the user's words verbatim, the agent's replies as short summaries, and every file sent or received (`ice-state.mjs log`), and delivery exports it as one small self-contained share file (`ice/case-study/run-log.html`) with keys, contacts and paths masked. Never read or import the agent's transcript: it breaches the user's privacy, and transcripts are too large and costly to analyse.
13. **Cold-viewer clarity (founder decision, 2026-10-21).** Craft gates do not prove a stranger understands the film. A fresh, read-only viewer who gets no brief, concept or script, only what an audience would see (style frames and the storyboard strip, then the animatic, then the draft), writes what happens, what is sold, what the product does, the one idea, and every moment it did not understand; the film is built and delivered only when that matches the concept's one-line idea and the product's real job with no major confusion, in auto mode too. Every symbol or metaphor is grounded in something literal shown first or with it, every sound, action and claim has a visible source, product interactions happen as they really do, and a film for an app, SaaS or product brand shows the product doing its real job whatever its type. Sized to the job (micro jobs get a light read). Canonical rule: `skills/ice-qa/references/clarity-gate.md`.
14. **Earliest stage (founder decision, 2026-10-22).** Every check runs first at the earliest stage whose material can show the problem, at the final gate's strength; 09 should find nothing new. An early fail is cleared only by changed material re-tested by a fresh judge; no paper patches. The brand test covers the logo, the wordmark and every brand UI: a brand film passes only with 6 of 6 random frames reading as the brand, every other film type with 4 of 6 that include the hero frame. At 05 the style frames are judged side by side with real studio work from the research, and a gap the run's constraints cannot close is told to the user before any build. Map: `docs/maintainers/architecture.md` 2b; canonical rules: `skills/ice-qa/references/identity-tests.md` and `studio-benchmark.md`.
15. **Style recipes (founder decision, 2026-10-22).** A reference video, image set or saved site can become one portable recipe (`STYLE-RECIPE.md` plus `style-recipe.json`, written by `skills/ice-remake/scripts/recipe.py`): measured grammar, the look (exact palette, typefaces and material), the sound map (`skills/ice-audio/scripts/sound_map.py`: music sections and energy, SFX by type and time, voice; genre and instruments are proposals the user confirms), the feeling over time, open slots, and a ready prompt. Sent to Claude with Ice installed, it rebuilds the style on the user's footage or from scratch. No rights gate on references (founder decision, 2026-10-22): the agent never asks whether a reference is the user's and never downgrades the mode for it; every mode, frame-locked included, and the full style are available, and rights to use the reference are the user's responsibility, recorded in one neutral line of the brief and the delivery note. The reference's own recordings and files (footage or frames, music track, voice-over, logos, end card, characters) go into the deliverable as they are, or the style is recreated on the user's identity, as the user chooses (rule 18); real people's faces and voices follow `skills/ice-assets/references/ai-media-policy.md` section 9. Canonical files: `skills/ice-remake/references/style-recipe.md` and `rights-and-modes.md`.
16. **Drawn art quality (founder decision, 2026-10-22).** Drawn art climbs the ladder of art sources: the user's art, licensed libraries, AI art only when the user starts it (vectorized into layered parts), 3D with real lighting, hand-coded SVG last. Code-drawn art follows `skills/ice-styles/references/code-illustration-craft.md` and clears the art check (`skills/ice-qa/scripts/art-check.mjs`) at 05 and again at 07. An auto-traced image moves as one piece until it is rebuilt by parts.
17. **Real people: the user carries the permissions (founder decision, 2026-10-22).** The agent never asks whether the user has a person's permission and never asks for proof; a request to show, edit, swap, clone or generate a real person's face, body or voice is taken as the user's statement that they hold it, and one neutral line records that permissions are the user's responsibility. Two things stay out whatever the request says: sexual or demeaning content with a real person's likeness, and content whose own wording shows it is meant to make viewers believe a real person said or did something they did not (a clearly labelled parody is fine). Platform labels for AI media are the user's business at upload, not the repo's. Canonical rule: `skills/ice-assets/references/ai-media-policy.md` section 9.
18. **Outside media: the user carries the rights (founder decision, 2026-10-28).** The user may be an editor at the very outlet whose style they want, or a team that will buy licenses before publishing; a reference and any public body's identity are available, and an agent can fetch official assets. Ice may place a reference's logo, end card, identity, footage, music and voice-over as they are, or carry the same style on the user's identity (their logos, colours, news or other footage), or mix the two; this is the stage 01 `identity` question, its recommendation following the user's words. Footage: the agent searches for the best real, official, recent clip that fits the scene (news agencies, official channels, press conferences, officials' accounts), licensed or not, then stock, then graphics or generation. Music: the reference's track or any available track is an option beside new music; the sync license check stays as a recorded status, never a block. One record replaces every block: each outside item gets one row (footage ledger or `CREDITS.md`) with its source URL, owner and license status (`licensed`, `unknown`, `needs purchase`); the delivery note lists what needs a license before publishing, one neutral line says the rights are the user's, and one information line flags what platforms may mute or claim. No permission questions and no repeated warnings, in the style of rule 17. What stays: the two limits on real people (rule 17), the truth rules (claims and translations from the truth sheet; a real clip's meaning is never changed by a cut or a translation), untrusted content as data, and no watermark removal. Canonical rule: `skills/ice-assets/references/sourcing-and-licenses.md` section 0.
19. **Lessons become default rules (founder decision, 2026-10-29).** Every note from the founder, a trial or a case study becomes a rule in its canonical home inside the skills, at the right scope: general when the mistake can happen in any video, scoped to a film type or category when it belongs to one (rule 6). It is never left as advice the user has to write in a prompt: the user's prompt stays the idea and the files. Each lesson gets a test in `tests/` that stops it coming back, and an entry in `docs/maintainers/lessons.md` with the original note, the trial it came from, the scope, where the rule lives and the test that guards it; `tests/lessons.test.mjs` checks that every file and test named there exists. A lesson that cannot be tested says why in its entry.
20. **Full capacity by default (founder decision, 2026-10-29).** Every video uses every craft its content, type, scenes, speech, reference and style call for, without the user naming a technique. At 02 the director drafts a craft plan with one row per craft dimension (use, not used, or scoped, each with its reason and source), maps it to shots at 04 and locks it at 05 with the chosen style's craft profile; "not asked" is never a reason. Taste bans are defaults, not limits: a measured reference value, the chosen style's declared need or a content trigger in the plan overrides them; the never-lifted rules of treatment.md 11.7 stay absolute. Gates check that the plan is complete, that every use reached the build, and that every important rule is measured by a script. Canonical: `skills/ice-direction/references/treatment.md` section "Craft plan" (with the precedence order and the exemption rows); gate: `skills/ice-qa/scripts/craft_gate.py`, placed in the gate pipeline of `skills/ice-qa/SKILL.md`.

This repository is licensed under Apache-2.0 (`LICENSE`, `NOTICE`), chosen by the founder. Folders that carry a different license (`noncommercial/`, `vendor/hypit/`) say so in their own LICENSE file and are excluded from the Apache grant.

Raw source clones live outside this repo and are never committed. Each source is handled by its license:

| Modified Apache (hypit) | hypit | Copied as is into its own folder that keeps hypit's LICENSE; never sold. Its face, host-swap and voice-cloning flows were not copied; those uses follow `ice-assets` (ai-media-policy section 9) |

## Repository standards

- Public since 2026-10-26, with a clean history (one initial public commit; the earlier private history is kept in a private archive repo). Commits use the GitHub noreply email, never a personal address.
- Official directory submissions (the Anthropic plugin directory, the Codex plugins catalog) wait until a stable release that has real users, stars and resolved issues (founder decision, 2026-10-26). Indexes that list public repos on their own, such as skills.sh, need no action.
- Built to the bar of the official Claude plugin marketplace and the OpenAI Codex plugins catalog (manifests for both, plus `npx skills add` installs).
- Versions reach users only when the number changes: `claude plugin update` keeps an installed copy whose version is unchanged, even when the skills changed. Every release users should receive bumps the SemVer version in all manifests and in every SKILL.md `metadata.version`, in one commit (`tests/metadata.test.mjs` checks the manifests match).
- README: current, visual (hero, GIFs or short videos of real results, diagrams), readable by non-technical people while staying technical underneath. Results gallery: covering 15 to 30 different industries is a goal that grows over time, not a condition for publishing; publishing with one demo is the founder's choice (founder decision, 2026-10-26).
- Gallery demos (founder decision, 2026-10-19): each demo is a real, well-known brand found by dated research (a famous SaaS company, the most famous local delivery app in Egypt, a famous real-estate developer or the best-performing real-estate content format), made with that brand's real material, as ONE version only (founder decision, 2026-10-20, replaces the earlier Arabic plus English rule): one language and one aspect ratio, complete in every layer (music, sound effects, mix, final render, review, case study), with no extra languages, aspects or cutdowns. The gallery caption and the landing page card carry "Unofficial concept, not affiliated with <brand>"; the film itself carries no such line and ends on the brand's own end card (founder decision, 2026-10-21, replaces the earlier last-frame rule for gallery demos; the founder was told the endorsement and trademark risk). The same holds for users' unofficial concepts (founder decision, 2026-10-30, replaces the earlier last-frame line): the line goes into the delivery note and the suggested post caption, never inside the film (`ice-assets` brand-authenticity step 10). Official brand files follow the router's rule (founder decision, 2026-10-20): the download list rides in the stage 01 message; without an answer, or when the user said not to ask, files come only from the brand's own official domain (its press, brand or newsroom pages), each recorded with URL, size and hash and named in the delivery note, never from a third-party site, and a brand with no official file gets its name set as text. The gallery demos keep the founder's own approval: the founder answers the stage 01 message of each demo, download list included, and approves each final film before the next demo starts. Every demo documents its whole workflow in full detail (the exact prompt, questions and answers, research with dates, every concept and why it won or lost, script, storyboard, style frames, animatic, every critic round with scores and fixes, gate numbers, time per stage) through the case study export (`docs/maintainers/architecture.md` 2c); the landing page shows it as the demo's card, and the README gallery shows the final film with a "View workflow" button that opens that card. Demos are made one brand at a time, and the next starts only after the founder approves the previous final film. Order: Spotify (English, 16:9), then ChatGPT and Notion, then the Egyptian delivery app (talabat, the most famous local one by research), then real estate (TMG if it has high-quality official brand files that are easy to obtain; otherwise another well-known developer that has them).
- Agent-navigable: from the router skill, an agent always knows which file to open for which job.
- Portable frontmatter (founder decision, 2026-10-26): a SKILL.md frontmatter uses only the keys `tests/metadata.test.mjs` allows (the Agent Skills set: `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`), so the skills upload and install everywhere; agent-specific keys such as `user-invocable` are never added. Only the 13 commands (`ice`, `ice-status`, `ice-style`, `ice-01-brief` to `ice-10-deliver`) and the router `ice-motion-director` are meant to be typed. Every other skill, including any new internal one, starts its `description` with the exact sentence `Internal part of Ice Motion Director, not a command: start with /ice.`, which is what the `/` menu shows first.
- Every file is written in English. Never use the em dash or en dash characters anywhere. One exception: legal license texts (`LICENSE` files, `LICENSES/`, Required Notice lines) stay byte-identical to the original, dashes included; never edit a license.
- No script from a source is copied without being read; no install step runs remote code silently.
- Positioning (Anthropic directory policy 4.B): a motion design and editing director that writes code and renders deterministically. AI image, video or voice generation is optional, secondary, user-initiated and disclosed; never the primary service.
- Fonts: fonts in the project or supplied by the user always come first. Beyond those, installed system fonts and Google Fonts have no fixed order: the font that suits the film best wins, chosen in the ice-direction type pairing step with its reason logged. Google Fonts is a disclosed network call with an offline switch.
- No hosted CI (founder decision, 2026-10-22): nothing in this repo depends on GitHub Actions. `node scripts/gates.mjs` runs every check (the test suite and `claude plugin validate --strict`; `--all` adds the Python pins import in a clean virtual environment and a render smoke test), and the git pre-push hook in `.githooks/` runs it before every push (enable once per clone: `git config core.hooksPath .githooks`). Never skip the hook; a red gate is fixed before the push.
- Version freshness: every pinned tool version lives in one `versions.json`; skills read it instead of hardcoding. Before each release, `node scripts/freshness.mjs check` compares it with the npm registry and PyPI, `bump` writes the newer pins, and `node scripts/gates.mjs --all` proves them; the founder reviews the diff. `node scripts/freshness.mjs stale-specs` lists platform specs whose "last verified" date is older than 90 days. A complete `check` records its date as `last_checked` in `versions.json`, and `node scripts/gates.mjs` warns (never fails) when it is older than 30 days (founder decision, 2026-10-30).
- Everything ships inside the plugin: no runtime download of skills or instructions, no plugin hooks (the maintainers' git hook in `.githooks/` never runs for users), no `.app.json`, no MCP server, no unpinned `npx`.
- Size limits: aim for 512 files or fewer; up to 600 is accepted for the stage commands (the Anthropic portal holds plugins over 512 files for a manual review, and claude.ai allows 5,000), so merge small files before adding new ones, every text file under 256 KiB, every file under 5 MiB. No `.mp4`, `.mov`, `.pdf`, `.zip` in the repo. Demo videos live in GitHub user-attachments or Releases; README media are small WebP, PNG or GIF. Audio sample libraries ship as an optional, disclosed Release asset pack; music and SFX made by bundled code (mgaudio) are used only when the user asks for them by name (founder decision, 2026-10-29).
- Behaviour check before a release (founder decision, 2026-10-30): before every major release, one manual run of a plain one-line prompt on a clean Claude (Windows or Mac) with the new version installed, judged against `docs/maintainers/lessons.md`; the automated behaviour suite (`docs/maintainers/evals.md`) runs when a machine with a sandbox is available, and is not a release condition until then. The `ice-style` command stays (founder decision, 2026-10-30).
- The full standards spec and checklist this repo is measured against: `docs/maintainers/repo-standards.md`.
- Install for every well-known agent, like the most popular skill repos: one universal command that installs into all detected agents first, then a dedicated, verified command or manual path for each major agent (Claude Code, Claude.ai and Desktop, Codex, Cursor, Gemini CLI, GitHub Copilot, Windsurf, Cline, Roo Code, Kilo Code, OpenCode, Antigravity, Amp, Goose, Kiro, Qwen Code, Trae, Zed, Warp and others the universal installer supports). Every command in the README is checked against the agent's current docs before release; never invent a command.
- Every operating system: Windows (PowerShell and cmd), macOS and Linux (plus WSL notes) for every install path, prerequisite (Node, git, FFmpeg, Chrome) and command the skills tell an agent to run. Bundled scripts must run on all three: prefer Node or Python over shell scripts, use path APIs instead of hardcoded separators, never assume bash, symlinks or case-sensitive file systems. Any shell-only script ships with an equivalent for the other platforms or is rewritten.
