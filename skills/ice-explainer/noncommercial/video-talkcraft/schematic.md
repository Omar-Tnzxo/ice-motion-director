# G5 Line-Art Schematics (the second layer for text-only shots)

> Canonical source: this file (rules + semantic graphics dictionary); code `template/motion-systems/schematic.tsx` + `icons.ts` (generated by `scripts/fetch_icons.py`);
> SKILL.md ④ layout budget and ⑤ global systems each have a hard rule pointing here. Added to the library 2026-09-07.

## 0. Why this layer exists

The user, watching the first-cut talking-head video on 2026-09-07: "Many shots without image footage are just text animations piled up; it's too monotonous." The reference given was a 275s explainer with **zero bitmaps and zero live footage** that still does not feel monotonous ("RAG and Knowledge Bases").
Taking it apart, the mechanism that keeps it from being monotonous is not in the background but in these points (the starfield background belongs to a different style tier, which this library does not install):

1. **Every abstract sentence gets a line-art schematic**: icons + boxes + arrows + small labels. Of 44 content shots, 29 are "white-line simple diagram + labels", and only 8 are pure big text.
   Talking about "chunking" draws a document page cut into blocks, talking about "detours" draws two roads, talking about a "store" draws a cylinder. Text only serves as labels and conclusions.
2. **Text is never bare**: every word sits in a container (pill / box / color block), and the container itself is an "object".
3. **Beats are bound to subtitle chunks**: within ±3 frames of each subtitle chunk's start frame there must be a visible action (entrance / color change / draw-on / pulse), on average one visible change every 1~2s.
4. **A small, unified entrance vocabulary, with density made by staggering**: only four kinds (fade-in-rise / slide-in / scale / draw-on); 1~2 frame staggers and an 11-frame gray→accent color change turn the same action into a ripple.
5. **Semantic graphics replace footage**: document = dog-eared page + lines, model = dot-matrix square, store = cylinder, space = grid + scatter points, index = slanted plane: all ≤30 lines of SVG.
6. **Color is semantics**: accent = the current focus; gray = inactive / context; white (or ink) = structural color; semantic colors only go into charts and warnings.

Its camera is static for the whole film, and all the sense of motion comes from 1~5; this library keeps G1's very slow push-in/pull-out and adds this layer on top: **both layers**.

## 1. When it is mandatory

- **Shots whose footage row has only "text"** (chapter cards excepted): the layer matrix must have one more row, "supporting graphic": one of line-art schematic / icon / connector / card stack / task card,
  and you must be able to say in one sentence how it relates to that line of narration. `preflight.py` issues a WARN (advisory) for text-only shots without this row.
- Shots where a single video is the subject do not belong here (that is the video container border `theme-frame.tsx` of design-language §1.3); shots with screenshots / images do not belong either (those are evidence cards + annotation cards).
- One graphic per shot: the schematic and the text title are two halves of the same subject group, not a fourth subject (the on-screen budget is still ≤3 groups, cinematography §4.5).

## 2. Vocabulary (schematic.tsx)

| Piece | What it does | Crucial point |
|---|---|---|
| `Sketch` | A transparent SVG stage covering the frame | Coordinates are in stage pixels; for portrait pass width/height |
| `DrawPath` | Draws any path in one stroke (`pathLength=1` + dashoffset), can be dashed (revealed by mask), can be filled after closing | power2.inOut near-constant speed, constant line width, rests after drawing (borrowed from outline-box-title) |
| `DrawIcon` | Iconify lucide line art drawn segment by segment in relay, 24→size | Stroke only, no fill; the icon is an "object", not decoration |
| `Connector` | Quadratic Bézier connector (bow height), optional arrowhead | Line arrives first, head grows after (arrow appears only at 96%); leave space at the arrow tip so it does not poke the text |
| `Node` | Circular node with back.out pop + label lagging 2 frames | Solid accent = current / white fill = normal; pops only after being "lit" by a connector (borrowed from step-timeline-vertical) |
| `Plate` | Rounded plate drawn in one stroke around (starting on the top edge, left of center), then filled white | Skeleton for cards / task cards / prompt cards |
| `Panel` | A non-drawn frosted white board (pass dark on dark backgrounds) that lifts the line art off the blurred base | The container for "text is never bare"; alpha .58 |
| `Cross` / `Tick` | Two-stroke cross (semantic color strike) / one-stroke check (accent) | Negation / confirmation use only these two gestures, no emoji |
| `Traveller` | A small dot traveling along a path (follows the line head) | Same at/dur as DrawPath to stick to the line head |
| `Label` | SVG text fade-in-rise | Readable on a 390-wide phone only at ≥36px; below 30px treat as decoration |
| `polyD` | Multi-point polyline / smoothed polyline d | Routes like "detour vs straight road" |

Everything is driven by `abs` (absolute seconds), beats come from word anchors in beats.json; zero randomness, zero ref measurement (seek-safe).

## 3. Semantic graphics dictionary (write the relationship sentence first, then pick the shape)

| The narration is about | What to draw | Example |
|---|---|---|
| Document / article / rules | Dog-eared page + 2~3 gray lines; multiple = card stack (offset +12,−30) | "Keep piling on prompts" = card stack grows to five → crossed out → three fall away + "−3" |
| Model / system / engine | `brain-circuit` / `cpu` + dashed or thin solid ring | "Model improvements" = core ring + three satellite lines |
| Comparison / trade-off / path | Two routes A→B (gray dashed detour vs accent straight road) | "Faster = fewer detours" |
| Steps / process | Pills + arrows in a row (current step accent, the rest gray) | Parse → chunk → vectorize → build index |
| Negation / don't | Icon + red cross at the top right | "Don't just ask chat questions" = dialog box + cross |
| Confirmation / done | Checklist dots + ticks | First two items on the task card ticked |
| Categories / several directions | Central hub fanning out to N nodes (connectors drawn first, nodes light up after) | "Four directions" = speed / frontend / code / writing |
| Task / complex job | Rounded task card: title line + checklist drawn item by item | "A real, complex task" |
| Store / storage | Cylinder (elliptical lid + vertical lines on both sides) | Knowledge base / vector store |
| Space / similarity / clustering | Grid + scatter points + highlight circle | "Go to the index and find the nearest neighbors" |
| Quantity / scale | Number roll (`number-counter` card) + unit | "One million tokens" |
| Time / speed | Timer / gauge / ruler | "11 min 53 s" |
| Boundary / scope | Dashed box + ticks inside | "Judge boundaries more accurately" |

Rule: **a motif is a pattern, a schematic is an object**: the theme motif on chapter cards (chapter-title-card) sits in the background at low opacity; the schematic sits on the subject plane, ink 3px, fully opaque.

## 4. Beat and stagger discipline

- **At least one visible change per sentence**: every beat of the schematic hangs on a word anchor (draw a line / light up / cross out / drop a card); the answer to a `beat_gap_check` gap can be "the schematic is drawing".
- **Don't let the boundary swallow the last beat**: finish drawing ≥0.5s before a chapter-card press-in / push-through exit (measured on three shots on 2026-09-07: the fan-out, the third satellite and the "−3" badge were all eaten by the boundary).
- Stagger standards: nodes 1~2 frames, cards 2 frames, icon segments 0.04~0.08s each, connectors 0.18~0.45s; the 0.3s gray→accent color change is a narrative action in itself, no extra displacement needed.
- Use only four entrance types: fade-in-rise / slide-in / scale pop / draw-on. No glitch, no jitter, no breathing.

## 5. Placement self-check (copy into that shot's self-check column in SHOTBOOK)

- Write the relationship sentence in the SHOTBOOK layer matrix ("G5 ... ← talking about X, so draw Y"); delete any graphic whose relationship cannot be stated.
- The schematic's bounding box does not intersect text / cards / the subtitle band, and is ≥64 from the frame edge; hub / connector start points are outside the text bounding box (a connector through text = P1).
- Multiple connectors **follow the same order as the items** (top → bottom) and do not cross; leave 14~18px of space at the arrow tip.
- The whole group (text + schematic) is centered within ≤48 of the frame center (layout.md §9 ④); the schematic takes the empty quadrant on the right / bottom, and the text group moves left or up accordingly.
- One skin: ink 3px + accent; on dark-background shots switch everything to dark tokens; gray dashed lines mean only "the rejected road", and are not also used as boundary lines.
- Labels ≥36px or admitted as decoration; icons ≥72px; core graphic ≥20% of screen height (v1 measurement: a 150px core was invisible on a 540-wide composite).

## 6. Optional skeleton: persistent HUD (install only when the user asks)

The reference film has one more layer: a top chapter pill (small bilingual Chinese-English text), an in-chapter step tracker (current step highlighted), and a thin bottom progress bar with the chapter name.
It gives "even the emptiest shot a skeleton", but it conflicts with this library's Apple paradigm of "content is the star, layout steps back", so it is **not installed by default**; when the user asks for it by name, implement it with the `chapter-progress-list` card + the screen-space layer (not inside the camera),
and declare it in SHOTBOOK §0.

## 7. Anti-examples

- The schematic has nothing to do with the narration (talking about speed but drawing a geometric decoration); four text-only shots using the same graphic.
- Graphics that look like icon-library stickers: filled, colored, shadowed: that is illustration, not line art; line art is stroke only.
- The schematic steals the text's spotlight: the core graphic > 45% of screen height, or a second accent color is used.
- Lines growing on their own, dots lighting up on their own, with no sequence: "light up where the line reaches" is the entire semantics of this layer.
- Letting the schematic replace footage: when real screenshots / screen recordings exist, the real image must be used (SKILL.md ③ real-image hard rule); schematics only fill in "abstract lines with no footage".
