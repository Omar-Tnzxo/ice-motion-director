## QC (one per chapter)

First read <skill path>/reference/agent-qc-rules.md, then the "Persistent layers", "<Gn>", "<Gm>" tables and "Global constraints" of <project root>/storyboard.md, <project root>/script/timeline.md, <skill path>/reference/style-guide.md, and each group's BUILD_NOTES (known deviations are not reported again). The final cut frame by frame is <project root>/fin_frames/f_%04d.jpg (<TOTAL> frames in total); first run `python3 <project root>/scripts/frame_metrics.py --frames <project root>/fin_frames --storyboard <project root>/storyboard.md --out <project root>/qc/frame_metrics_v<N>.md` and merge this chapter's empty-stage / no-light / debris flags into the report; then run `python3 <project root>/scripts/motion_check.py --frames <project root>/fin_frames`, and for this chapter's shots with stillness >40% or longest stillness >1 s, look at the frames to judge (changed pixels <800 truly still → medium; 800-2500 small-area action → low, suggest a larger amplitude); then use PIL to build a contact sheet every 30-60 frames and read it through; check the "Set piece list" and "Camera move list" item by item against the frames. **Do not modify source code.** Output <project root>/qc/qc_v<N>_C<k>.md, appending as you check, at least one conclusion line per shot; issue rows `| Severity | Shot | Frame | Symptom | Criterion | Suggested fix |`. Final reply: count of high / medium / low items, the 3 most severe, file path.

## Final check
You are the final inspector for the finished film. v<N> has been rendered. Write three things to <project root>/qc/qc_v<N>_final.md: (1) Flicker compliance: for each of the film's <number of shots> shots pick 2-3 element entrance frames and build brightness curves over f0…f0+12, list the elements that actually flicker, and compare item by item against the storyboard whitelist (still flickering outside the whitelist → medium; missing flicker on the whitelist → low; HUD word changes should be fade-ins); also verify the sweeps: shots showing three-pass purple light sweeps must exactly match the storyboard's "light-sweep whitelist" (≤2), any extra → medium; (2) re-check the items left over from the previous round one by one; (3) regression read-through with a contact sheet every 40 frames; (4) run `scripts/frame_metrics.py` to re-check composition and light (empty stage / hero without light / debris) and `scripts/motion_check.py --frames <project root>/fin_frames` to re-measure continuous action (**group-level readings are too lenient, the re-measurement on the final film is the criterion**: look at the frames for every shot with stillness >40% or longest >1 s), and confirm each item of the set piece list and camera move list against the frames. Do not modify source code. Final reply: N places outside the whitelist / N missing flickers, results of the leftover re-check, counts of frame_metrics high / medium / low, number of new issues and the 3 most severe.

## Dispatch and watchdog (for the main session's own use)
- Concurrency is limited by the pane cap of this machine / the harness (before dispatching, use ListAgents to see machine-wide usage; the safe approach is waves of 4); TaskStop finished agents promptly to free resources; for an agent killed by an API error, first SendMessage it once, and if there is zero output for 10 minutes, TaskStop it and re-dispatch ("reuse the half-finished work on disk, only complete the unfinished parts"). ListAgents / SendMessage / TaskStop are Claude Code tool names; other harnesses use equivalent operations.
- Check the mtime of each group's index.ts / BUILD_NOTES every 30-40 minutes.
- Answer a build group's ruling requests in one sentence; when adjacent groups share elements, specify the import direction, do not make the two groups align with each other.
- Messages can get swallowed while an agent is writing its final report: if its idle notification still says "waiting for a decision", resend once.
